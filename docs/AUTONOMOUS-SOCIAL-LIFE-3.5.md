## 已定位的体验断点

1. 所选 MiMo 凭据实际存在于当前 Hermes profile，但社交纯文本路径仅看环境变量；
   普通 direct 路径还仅覆盖 custom/openai-api + Keychain，MiMo 落回 CLI。
   `model-credentials.js` 只读取选定 provider/profile/完整服务路径匹配的 API-key
   记录；显式 Keychain 不可用不降级，不跨服务借密钥。direct 和纯文本路径复用解析。
2. 主人发表情以前只取本地候选。现在接入同一个 public-sticker resolver：本地优先，
   空库才搜索，实际图片下载/视觉资格/哈希缓存仍走原库，发送仍走原 OneBot gate。
   主人明确目标的单次内容授权与自主参与范围分开，不保存扩大群范围的配置。
3. Memecub 匿名和已认证额度分开；密钥只注入官方 Bearer 请求头，缓存命中不记
   新搜索调用。429、凭据失败和图片拒绝不热重试；只有空结果允许一次通用词替代。
4. 新增偏好/委托只使用原 MemoryRuntime 与 TaskRuntime；没有第二发送器或永久思考循环。

## 基本边界

本轮允许普通低风险社交自主行动，不逐步审批。真实身份、已授权目标、quiet、
撤销、现有预算、实际回执及私人内容隔离继续生效。持续目标不是无限授权；
不确定外部写入不重放，管理员取消优先于尚未执行的后续步骤。
空间持续授权只在既有受众内处理有公开来源的低影响素材，不扩大可见范围。
需要预览时引用管理员私聊中的确切预览回复“发吧/不发了”，绑定实际发送者和版本。

## 实际实现

- `owner-social-controller` 用原始 OneBot 私聊身份、会话、消息摘要和当前配置核实
  主人输入；一次语义分类区分持续目标、已有目标修正、行为指导和普通聊天。
  持续目标写入原 TaskRuntime。动态能力表涵盖当前群上下文、人物/自身记忆、
  已核实公开发现、搜索、表达、一次性后续判断、空间草稿及实际支持的空间交互。
  不提供 shell、电脑控制、任意文件或新的跨群联系人权限。
- 工具调用逐步持久 claim，真实回执单独结算。搜索工具结束后旧 signal 必须失效；
  后续发表情重新打开当前工具的内容上下文，只能使用先前真实候选与当前资格的交集。
  原 ReplyPlan 版本、消息条数和真实候选检查仍生效。结果 uncertain 不重发。
- 新的人类群事件可继续该群已有 waiting 目标；同一原始事件不能重复唤醒。
  一次性后续判断复用原 15 秒机会调度，不增加发送队列或常驻思考循环。
  quiet、账号换绑、目标撤销、暂停、配置修订、预算不足均会阻止执行。
  重启后旧目标保留，只读恢复，未知写入不重放；新的主人指令与重新核验仍可继续。
- `owner-guidance` 在唯一 MemoryRuntime 中保存有来源、有版本、可更正与撤销的
  类型化规则。配置的群审核员必须真实 @ 当前 Bot，且只能修改该群的表达行为。
  称呼仍沿用既有 Owner First 路径。提示词和最终发送闸门共同使用当前规则；
  消息回应、拍一拍、表情、语音也不能绕过停止要求。
- 空间持续授权只在原受众与已启用能力内生效。发布来源只能是本账号真实公开
  Discovery 素材或管理员预配置主题。读取私人空间会持久标记委托，随后不能将
  其上下文用于群表达或公开搜索。委托开始/过程/私人目标不会发往目标群。
- 旧人物重建由只读 source worker 分页读取原记忆及授权群存档；模型在事务外做
  有界语义整理，结果经原 writer 发布。未核实 Bot 归属不补造历史共同经历；
  Supported 只在原群作不确定参考，Verified 仍需原消息/QQ/时间与真实归属。
  删除、纠正、冻结和跨群隐私门禁优先于旧摘要。进度、暂停/继续接口受本机认证与 CAS 保护。
- 自动化和人物记忆原有页面增加只读摘要，不新增侧栏。未知用量不显示为零，
  读取摘要不保存配置。总览现在显式提示记忆只读保护，不再因 QQ 在线显示“一切正常”。

### 表达与工具组合示例

以下为**设计示例，不是真实聊天记录或实测效果**；按账号人格选择，不作为固定回复。
括号中的工具动作必须以宿主能力、来源与实际回执为准，不能把示例当执行授权。

| 场景与输入 | 合理的表达/动作路径 |
| --- | --- |
| 开心聊天：“项目终于上线了！” | 温和账号：“终于能松口气了。”；俏皮账号可选实际“庆祝”表情，无需再附一段祝贺 |
| 熟人互损：“你算错了还挺自信。” | 承认并改正：“刚才自信比算力先到了。”；不为接梗保留错误答案 |
| 冷场：上一条没人接，已转向晚饭 | observe，放下旧梗；没有新素材不催问“怎么没人理我” |
| 多人讨论：甲问乙，丙已回答 | 跟随引用分支；没有独特补充不主持，有来源时只补相关的一点 |
| 斗图：对方发轻松反应图 | 先查合格本地候选，必要时用公开情绪词搜索→下载/视觉资格→选择候选→真实 ACK；拒绝项不能绕过 |
| 被 @：“刚才那张图什么意思？” | 读取实际引用图片并说明；若识图失败，说明没看清，不凭昵称猜内容 |
| 认真求助：“我现在只想找人说说。” | 先倾听，不急着给解决清单，不把痛苦当互损素材 |
| 管理员连续纠正：“活泼点。”“别太吵，多表情少长文。” | 真实身份核验→保存同一账号/范围的指导修订→回读；合并约束，不另起冲突规则 |
| 持续委托：“在演示群找机会聊摄影。”“不要语音了。” | read_context→更新原 TaskRuntime 目标→查公开素材→合适时 express；无新输入交回事件调度 |
| 自选语音或图片：生日祝福，语音可用 | 账号偏好和语境可选择语音；不可用则诚实文字降级，不声称已生成或发送 |
| 跨群遇到同一 QQ：“上次说的游戏……” | 检索该逻辑 Bot 获准的非敏感人物信息，叠加当前群语境；另一 Bot 经历和私聊秘密不搬运 |
