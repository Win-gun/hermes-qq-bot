# Hermes 3.8：真实社交与持续人物记忆

## 起点与验收边界

2026-11-07 继续核对：GitHub `main` 基线 `c68a1ef` 的 CI 成功；生产 beta.40 的 App 哈希与先前部署 manifest 一致，两个 QQ 身份在线，MemoryRuntime 可写。未重置登录、模型、预算、人物原文或历史候选。上轮 18,555 个候选、7 条语义提案、20,077 个已知 Token 和 4 次未知用量原样保留，隔离的旧语义请求未重放，低收益历史迁移继续暂停。

真实事件核对以授权测试群为限：beta.40 上线后有 37 条群入站归档，与同消息、同发送人、同会话、同逻辑 Bot、同原始时间的来源回执逐条匹配；其中 0 条符合公开本人兴趣识别。不能因此宣布真实记忆写入成功，也不把普通群聊原文写进报告。实际兴趣保存、重启读回、回复使用和跨群真人场景仍须真实用户事件。

## 已修复的实际断点

- 自动群聊上下文按当前话题选择已获准的人物条目，每人最多三条、自动关联最多两个对象；不自动加载最近所有发言人的整份资料。保留来源时间与不确定性，不改变人物管理页的完整查询。Social Agent 的 `read_memory` 现在能读取当前真实发言者的 PeopleMemory，而不再只查情绪、共同经历与习惯。
- 同群、同逻辑 Bot、同真实发送人的明确否定可停止使用一个精确匹配的本人偏好。保留原版本、更正消息 ID、账号和原时间，在既有 MemoryIntake/MemoryRuntime 内提交；更正提升现有控制修订，未发出的旧上下文不能继续使用。旧来源不复活，不从否定推断新的喜好。不模糊匹配“之前那个”，不覆盖管理员或其他群、私聊及另一 Bot 的独立事实。
- 归档新增 `sourceTimeKnown`，明确区分原 OneBot 时间与接收时间回退；旧归档继续按原有来源回执校验，不能靠新增字段反填旧历史。
- 主人多轮委托缺目标或需要澄清时，使用真实回复格式化器读取的 `clarify` 字段，而非把问题藏在 `question`；不再只显示错误码。依旧复用原 TaskRuntime，不凭一句含糊的补充创建新权限或重放不确定动作。
- Memecub 返回过期／不合格候选，不再被当成空搜索而额外回退搜索一次；真正空结果仍保留原有的一次有界回退。未下载结果或没有实际 ACK，不算发送成功。

## 验收分层

隔离测试通过与生产 QQ 成功分别记录。核心覆盖：纯文本来源→实际 bridge 入站→人物持久化→重启读取→真实回复组装器的相关检索→精确更正→旧事实停止投影；不同 Bot、私聊、墓碑和当前会话权限不互相绕过。模型判断和真人自然度不是规则测试能证明的结论。

本轮没有为无来源旧摘要调用模型，也没有把模型评价当真人评分。九类场景沿用现有代表性回归（日常、照片、玩笑、挫折、多人、熟人、主人指导、表情、沉默），真实模型 3.7/3.8 对照及真人评分尚未完成；未虚报 Token 节省或生产 P95。

## 真实 QQ 仍需的最小输入

1. 在已授权测试群由真实本人发一句非敏感兴趣，不用 @；确认持久化后，再发送带具体对象的明确更正。模糊指代不自动删除。
2. 主人私聊指定 Bot，给出明确测试群的长期指导，再提出同群持续目标；收到实际任务编号后补充或修正同一任务。核对任务 ID、版本、实际上下文工具及回执，不把模型“做完了”当成功。
3. 两账号的测试群均可普通回复，但不在已保存的自主 Social Agent／表情范围内。尚未收到针对该群临时自主验收的新增明确授权，保持原状，不扩大全局群范围。未获得真实自主选图、Memecub 请求、QQ ACK 或回读证据。

## 部署与回滚

本轮必要 App 更新按用户任务书授权执行，部署前停机备份旧 App、配置与完整数据树，核对哈希和独立读回，再启动并核对版本、账号身份、OneBot 与唯一 writer。配置出现新修改时拒绝覆盖。回滚只替换经 manifest 验证的旧 App；不直接用旧数据覆盖上线后的新消息、控制和回执。所有备份与身份资料仅保存在本机私有目录，不提交 Git。
