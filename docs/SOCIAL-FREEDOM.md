# 自主表达与 QQ 空间私聊确认

## 本轮边界

普通消息、表情、语音和原生动作由现有 Social Agent / ReplyPlan 选择，不增加人工逐条审核或第二个发送器。自主不等于必须说话，也不等于无限调用。保留现有账号、会话、quiet、撤销、预算、真实回执和多账号隔离。

本轮重点是发送内容的决定权，不开放数据删除、任意电脑工具、第三方声音克隆或读取其他账号私聊的权限。内容审核减少不等于取消当事人隐私或声音授权。

空间是公开边界：AI 可以自己拟稿和选公开配图，但发表前将**精确正文、受众、全部配图和确认指令**放在同一条管理员 QQ 私聊消息中。管理员确认后只执行该版本；不用回控制台批准。

用户已在本轮授权构建替换 App 并给两个现有账号启用上述能力；保持原群范围与预算。部署完成前源码检查不等于已上线。没有把此授权扩展为任意 QQ 实发、读取私人磁盘或更高权限。

## 设置与兼容

- 账号 `socialExperience.stickers.autonomousSelection`：经自动图片检查的素材可由 AI 选择，保持 candidate 身份，不伪造管理员 confirmed。旧配置默认为 false。
- `stickers.webSearch`、`stickers.maxDailySearches`：允许公开 Memecub 检索及每账号日预算；默认关闭、12 次。共享 IP 另有全局 20 次/日持久化上限。现有视觉学习预算不提高。
- `qzone.reviewTransport: "qq_owner"`：QQ 私聊确认；未配置时保留原 console 流程。`qzone.enabled`、`publish.enabled`、受众和日限额仍使用现有配置，不能因切换确认位置而暗中扩大受众。
- `vision.preferChatModel`：保存时由本机管理 API 为各账号当前问答绑定生成管理员能力快照。模型、服务地址或连接变化后不再沿用旧断言；能力未知时走现有独立识图方案。

页面入口仍在原账号社交表达、账号空间和识图板块；不新增侧栏。各区域沿用原 CAS 和草稿保存机制。

## 表情和公开配图

`search_stickers({query})` 属于原 Social Agent 的有限工具调用。只发送公开短语，不上传整段聊天、QQ 或私聊。宿主拒绝当前已知成员名、明显凭据及标识；这不是对所有隐私文本的完美识别器。

Memecub 仅作公开检索来源，使用官方 REST API，无新增 npm 依赖、登录或购买。仅检索 meme/gif/emoji 候选；不抓取网页全文或执行返回的 Markdown/指令。要求署名的素材暂不自动发送，避免遗漏署名。供应商许可字段保留为来源声明，不当成版权保证。

候选经现有 public-media 下载器（公开地址解析、DNS 固定、重定向和大小检查）读取实际图片，再由当前识图路径判断是否为可复用且无私人内容的表情。缓存采用原账号的内容寻址 sticker cache；源 URL 不进入模型表情 ID。明确拒绝仍优先，不能靠再搜索同一图片绕过。

搜索不是发送命令。AI 可以不用结果，或只用一张表情；普通 ReplyPlan 和最终发送门继续核验实际可用 ID。不会把下载或识图成功说成已经发到 QQ。

公开搜索图片可作为空间配图；群友照片、聊天截图、私聊图片和群观察缓存不能因此变为空间公开素材。发布使用经验证的 base64 图片字节，不接受模型传入 URL 或文件路径。运行时上限9张、单张5MiB、合计20MiB；主机当前缓存最多8张、1小时，按逻辑账号隔离。

主机公开配图证明目前保存在内存中。重启后旧带图草稿保留，但缺少图片证明时不能预览/发表；不会自动重放。不要将这点误报为完整的持久化图片恢复支持。

空间配图另经过有界容器检查，拒绝 EXIF/IPTC/XMP、文本元数据、未知块及尾随内容；仅支持 PNG/JPEG/GIF/WebP 的严格子集。无法证明容器适用时仍可按原策略用于聊天，但不能成为空间配图；不默默剥离或上传隐藏数据。容器检查不代替视觉隐私判断和管理员预览。

## QQ 确认闭环

1. 原 QZone Runtime 创建正文和有序图片哈希绑定的草稿。
2. 唯一 MemoryRuntime writer 落盘预览 claim，再向配置的第一位真实主人发送私聊。只在收到有效消息 ID 后记为 awaiting_owner；不确定发送不重试。
3. 管理员30分钟内回复 `/bot qzone confirm <token>`，或 `/bot qzone reject <token>`。
4. 宿主验证真实私聊发送者、接收账号、逻辑身份、物理 QQ、配置/连接修订、正文/受众/配图、期限和当前权限，落盘发布 claim。
5. 通过原审核租约、QZone 发送门和回执核验执行；接口受理只报 accepted，不报客户端已可见。

Token 是随机单次引用，不是身份。其他人看到或转发 token 不获得批准权。更换载体、配置变化、超时、重复确认、内容/图片变化均不能重用旧授权。备份/恢复不唤醒这些记录；不同配置/载体修订使旧确认失效。

空间创作只给专门的无工具模型调用提供已验证公开主题和当前人格文风，不提供私聊、群聊天、人物档案或私人动态。程序敏感信息过滤、公开来源门和管理员预览共同构成边界；不能宣称仅靠正则或模型就可证明“绝无隐私”。

## 历史与识图

`read_history` 可带 query，通过原后台 archive search 检索当前会话的有限历史。私聊目录继续按独立账号隔离；不开放任意本机路径、其他账号私聊或跨群原文。历史检索不推进未读水位，也不能充当新的互动证据。直接问答仍保留快速路径。

旧识图实际使用 Hermes CLI `--image`，并非直接给聊天 API 传图。新增 `vision-completion` 使用 OpenAI-compatible Chat Completions 的实际 data-URL 图片内容，不把路径当图片发给模型，不携带模型工具权限。支持取消、超时、大小限制、身份重查、明确错误及真实 usage；CLI 无可信 usage 时仍 unknown。

不按名字猜模型支持多模态。管理员选择当前问答方案并声明支持图像后才能走直接路径。调用失败不再偷偷试另一个模型；不会静默更换密钥。API 管理中明确测试独立识图模型时仍测试该方案，不能被“优先问答识图”劫持。

## 验证与未验证

新增入口 `npm run test:social-freedom`：表情自动选择、拒绝优先、公开来源、Memecub 假网络/假 DNS、图片 hash/审批、QQ 预览单次确认与失败不重试。

`social-life-integration-self-test` 使用临时 HOME、两个假 OneBot 和假多模态 API；验证控制台不能批准 QQ 模式、其他账号不能消费 token、确认精确发布一次、保存图像能力快照、实际图片字节进入问答 API且测试不向 QQ 发消息。旧生命周期、社交主体性、人物/主人、备份、API、配置和控制台回归分别运行。

独立风险审查发现并修复4项 P1：旧收藏描述不足以证明隐私/复用资格、同哈希跨来源绕过拒绝、历史工具绕过人物删除栅栏、QQ 确认后的 quiet 竞态。`social-freedom-regression-self-test` 执行桥接实际回调，34项覆盖冻结/撤销/删除前后、审批落盘和发送排队期间 quiet、旧载体 token、公开图片来源/哈希/撤销/账号隔离。不是仅用源码字符串断言代替行为测试。

尚未验证真实供应商识图质量、Memecub 线上可用性/效果、真实 QQ 私聊预览与带图空间发表，以及真人体验。测试全绿不代表这些效果验收已通过。

QQ 私聊确认本轮接通的是空间发表，不包含点赞/评论的自主执行。QQ 确认模式下这些互动提案尚未接入私聊审批，不能视为已开放或已完成；控制台不会因此获得绕过 QQ 确认的权限。普通聊天的 QQ 消息回应、表情和拍一拍仍走原有独立能力与发送门。

识图测试接口原有 PNG 样例存在损坏；已替换为经过 CRC、解压与尺寸检查的32×32红色 PNG，并对两个真实接口样例增加回归，避免将坏样例误判为模型不支持图片。

## 本机部署验收（2026-10-29）

beta.30 已构建并替换安装版，两个现有账号开启自主表达、公开表情检索及优先问答识图；按最新保存配置写入并读回。原会话范围、模型绑定、人格、语音及已有数值预算保持不变。空间发布切换为管理员 QQ 私聊逐版本确认；原账号保留好友受众，原先未配置空间的账号保留仅自己受众，不隐式扩大为公开。

安装前后验证2/2 OneBot 连接、配置 QQ 与实际 QQ 一致、唯一记忆 writer 可写、签名与包内源码一致。旧版出现过写入不确定保护，已备份后关闭重开恢复磁盘视图，未重放不确定操作；这不代表已定位或永久修复原超时原因。旧 App、停止时状态快照与未创建的编辑草稿均保留在本机回滚/工作产物中，不进入发布包或 Git。

此部署验收不等于真实供应商图片质量、QQ 预览/空间实发验收；本轮没有为了测试向真实群或空间写入。源码已本地提交，未据此自动推送 GitHub。

## 回退

保留原模型绑定、风格和数据。关闭 `autonomousSelection` / `webSearch` 或恢复之前账号策略即可停用新能力；QQ 确认记录保留不重放。回退 App 之前需保留新产生的状态和拒绝记录，不能用旧备份覆盖较新的私人记忆。
