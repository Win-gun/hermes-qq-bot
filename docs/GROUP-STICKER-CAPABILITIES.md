# SnowLuma 能力核查与群聊表情自主学习

核查日期：2026-10-24。本文是调研和后续实施方案，不代表新功能已部署。
本次未修改运行配置、账号策略、记忆或安装中的 App；未发送 QQ 测试消息。

后续已按用户要求实现群表情学习和消息表情回应的源码增量，实施与验收边界
见 [Social Experience 台账](SOCIAL-EXPERIENCE-2.md#后续源码群表情自主学习与消息表情回应)。
下面的“当前实现”描述调研时基线，不是对增量源码状态的替代说明。

## 1. 已确认的边界

两个在线账号的 `get_version_info` 均返回 `SnowLuma 1.12.0-node`，状态正常。
主账号只读查询结果如下；群数据仅在内存中核对响应形状，不保存或输出正文、
图片地址、文件标识、昵称和鉴权信息。

| 接口 | 实测结果 | 能证明什么 |
| --- | --- | --- |
| `can_send_image` / `can_send_record` | `retcode=0, yes=true` | 协议自报图片/语音发送能力，不是本次真实发送验收 |
| `get_group_msg_history` | 成功，限量返回近期消息 | 当前授权群的近期消息可读取；不能推导全量历史可恢复 |
| `get_image` | 从实际收到的图片引用解析成功 | 返回可用 HTTP(S) 地址及图片元数据；没有下载或做识图调用 |
| `fetch_custom_face` | 成功，当前返回空列表 | 基础收藏列表接口存在，但没有可用于本次验收的收藏 |
| `fetch_custom_face_detail` | `1404` | 当前版本不支持详情接口；不能误报为整个 QQ 图片能力不支持 |
| `fetch_sys_faces` | `1404` | 当前版本不支持该系统表情目录动作 |
| `get_group_todo_list` | `1404` | 当前版本不支持该群待办查询动作 |
| `_get_group_notice` | 成功，当前为空 | 公告读取接口响应正常，不证明公告发布权限 |
| `get_group_file_system_info` | 成功 | 群文件系统元数据可读，不证明任意文件可下载或上传 |

群聊样本里的图片段包含 `url/file/sub_type/summary`。本次观测到的
`sub_type=0` 不能当成表情包确证，普通图片仍需分类，不能全部收为表情。

## 2. 上游能力与当前版本不能混同

官方最新发行版为 [v2.1.1](https://github.com/SnowLuma/SnowLuma/releases/tag/v2.1.1)，
固定参考提交 `f8cb15c27bca3d2d1bd044a921e55bfc44bb5e60`。
该提交的 [MCP 动作目录](https://github.com/SnowLuma/SnowLuma/blob/f8cb15c27bca3d2d1bd044a921e55bfc44bb5e60/packages/mcp/src/generated/catalog.json)
包含 200 个声明式动作；数量包含占位、未实现或待验证项，不等于 200 个已可用功能。
HTTP 成功也必须检查 OneBot `retcode`，不能把响应收到当作执行成功。

| 能力方向 | 上游目录中的例子 | 对本项目的用途与限制 |
| --- | --- | --- |
| 群表情理解 | `get_image`, `ocr_image`, `get_group_msg_history` | 获取图片与上下文；图片理解、时机学习仍由本项目实现 |
| 原生表情 | `fetch_custom_face_detail`, `send_custom_face`, `fetch_sys_faces` | 收藏详情与原生样式发送；当前版本部分不支持，不能直接启用 |
| 轻量社交 | `set_group_reaction`, `set_msg_emoji_like`, `get_msg_emoji_likes` | 贴表情回应、读取回应；比完整回复更轻量，但仍是受控发送行为 |
| 原生互动 | `group_poke`, `friend_poke`, `set_input_status` | 拍一拍及输入状态；须验证场景、目标、频率和回执，不自动开放 |
| 丰富消息 | `send_msg`, `send_group_forward_msg`, `get_forward_msg` | 图片、语音、视频消息段与合并转发；具体编码、大小、客户端效果要逐项实测 |
| 文件传输 | `upload_group_file`, `upload_private_file`, 流式上传下载 | 长报告与任务产物；容器路径不是宿主路径，需沿用任务文件授权与资源限额 |
| 群协作 | 群公告、精华消息、群待办 | 可扩展群助理；发布、删除、群管理须独立授权和相应 QQ 权限 |
| 群相册 / QQ 空间 | 相册媒体、动态、评论、点赞 | 可扩展，但涉及新数据范围及外部写入，不属于表情学习授权 |

不把接口命名当作安全判断：例如 `get_ai_record` 在官方目录中不是只读动作。
也不向社交模型开放 Cookies、clientkey、数据库密钥、原始 SSO 或任意动作执行。
SDK 的消息段构造器能构造某种段，不证明当前协议和 QQ 客户端可成功处理。
`get_recent_contact`、`.get_word_slices`、`set_restart` 等带占位/不支持说明的项
不得列作已实现能力。SnowLuma 提供 QQ 协议能力，不代替人格、记忆或社交判断。

## 3. 本轮新需求：从逐张审核改为受范围约束的自主学习

用户允许机器人读取学习群友发出的表情及使用时机，自行决定选用。
这意味着取消正常素材的逐张人工审批，不是开放所有群、私聊或所有 QQ 动作。
实施时沿用账号现有授权会话；是否扩展账号/群范围另行配置。

### 3.1 先补齐来源和证据

当前 `sticker-service.js` 只有“读取自己的收藏 → 视觉标注 → 人工确认”，
群语言 intake 也只统计图片数量。新增独立 `group-observed` 来源：

1. 从通过账号、会话和人类发送者校验的当前原始消息接入，不由模型伪造事件。
2. 分辨表情与照片、文档、截图。未知图片可分类，但不因在群里出现就自动复用。
3. 使用同一图片的内容 SHA-256 去重；保存消息 ID、真实时间和有限用途证据。
4. 语境由同消息文本、明确引用及短时间窗中的有限前后文组成。之后新到的
   相关人类消息可以追加证据，不为了凑后文阻塞正常回复。
5. 视觉含义和实际观察用途分开记录，例如“图上是鼓掌”与“本群用于反讽”
   不能等同。单次可学习明确用途，证据不足则保留不确定，不虚构群共识。

群来源不依赖收藏接口；也不自动把群友图片收藏进 QQ 账号。收藏同步只能
影响收藏来源，不能把不在收藏列表的群来源素材误停用。

### 3.2 自动资格不冒充人工批准

- 增加独立的群学习与自动选用策略，缺省关闭；保留原 `autoSend` 发送开关。
- 有效图片、非隐私内容、明确用途及有效作用域可以形成自动可用资格。
  不要求所有表情重复出现若干次，也不要求管理员逐张点击确认。
- 自动资格绑定图片 hash、来源证据和策略修订，不能伪造 `local-admin`。
- 管理员拒绝/禁用优先；重新观察、重新下载、模型重新标注都不能自动复活。
- 不将私人照片、证件、聊天截图、敏感内容或攻击性指令当可复用表情。
  图片内文字与群消息都是不可信内容，不能改变权限和核心人格。
- 沉默、单个点赞不是“全群接受”的证据。明确负反馈优先降低或停止使用。

### 3.3 学的是发送时机，不是见图就跟发

记录用途、适用话题、情绪/互动场景、不适用场景与证据可信度。生成回复前
做本地相关检索，最多提供少量候选；由当前账号模型在原有一次生成中决定
文字、表情或不用，不增加逐条串行审查模型。

学习完成不触发发送。认真求助、悲伤、工作任务、明确拒绝等场景抑制不合适
的玩笑；同群冷却、防刷屏、quiet、账号发送类型和最终 wire 身份检查保持。
只有实际确认发送的图片才记使用记录，不确定回执不自动重发。
表情含义和使用证据按逻辑 bot × 群隔离；可以共享底层图片字节，但不能共享
其他账号/群的解释、原始上下文或发送权限。

### 3.4 后台学习与磁盘边界

下载/模型调用在有界后台队列中进行，不占据直接回复关键路径；状态仍交给
现有唯一记忆写入器。模型调用沿用账号实际识图方案，计入现有视觉调用预算，
不建立隐藏供应商或偷偷提高预算。

建议首版限制：全局一个学习处理器、每账号最多 16 个等待项、单图 5 MiB、
受管内容缓存每账号 128 MiB、最多 500 个活跃索引。上述为待实现默认值，
本次未写入生产。容量满时背压或明确停学，不无限下载或清理人物记忆。
缓存采用内容寻址、0700/0600 权限，事件/模型不可指定本地路径。限额只管理
新表情缓存；清理可再下载缓存不得破坏发送收据、禁用记录和原有存档。
URL 过期时只能用合法当前来源刷新或停用，不绕过鉴权。普通备份只包含
规范化非凭据素材元数据和受限资产，不打包 QQ token 或临时签名 URL。

## 4. 推荐实施顺序与验收

1. **群表情 intake 和后台学习**：先在现有 1.12.0 可用的群图片链路实现，
   不把协议升级当作这一功能的前置条件。
2. **自动可用资格和语境检索**：保留拒绝优先，接回同一 ReplyPlan/发送闸门。
3. **管理可观察性**：按账号展示群来源、用途证据、自动可用/未知/禁用、
   下载与视觉预算、缓存占用；默认自主，管理员可以撤销，不需逐张审批。
4. **协议升级验证**：另建隔离数据/容器验证 2.1.1 的配置、卷、QQ 登录态、
   OneBot 兼容、双账号隔离，再申请生产切换。Docker 镜像必须核对实际架构、
   版本和摘要，不把 release 压缩包存在推导成镜像可直接替换。
5. **进一步原生互动**：优先表情回应，其次拍一拍及原生收藏表情；每项通过
   隔离测试、明确发送权限与真实回执验收后逐项开启，不一次性开放所有动作。

必测：群来源不被收藏同步删除；普通图片不误收；重放不重复学习；同图跨 URL
去重；上下文截断与不确定含义；模型/图片指令注入；隐私图排除；拒绝不复活；
跨账号/群不可串用；下载/识图期间 quiet、账号停用和策略修订；队列与缓存满；
预算耗尽；持久化失败；部分/不确定 ACK 不重发；聊天不等待后台学习。
