# P0：记忆可靠性、主人语义与委托安全续行

本轮以已有 Social Agent、TaskRuntime、MemoryRuntime 和发送闸门为基础。
不新增执行器、长期记忆 writer 或发送队列。本轮源码版本为 beta.37；
真实数据语义结果、生产部署、实际 QQ 回执分别记录，不能互相替代。

## 记忆只读复发

旧实现从请求发出时启动定时器，超时回调直接锁存 `MEMORY_OPERATION_UNCERTAIN`
并终止 worker。进程被挂起期间，宿主与 worker 都不能继续处理；恢复时，
到期定时器可能在 worker 完成写入／传回确认之前执行。

已用隔离子进程 `SIGSTOP/SIGCONT` 复现：1 秒 deadline、2.2 秒挂起，旧实现
拒绝在途提交并只读；同一输入在修复后落盘并得到实际确认。Mac 电源记录亦显示
本次运行期间多次合盖睡眠与维护唤醒，但旧版未记录故障触发细节，不能据此断言
每一次历史故障都由睡眠引起。

修复：

- 同步 structured clone 完成后再开始响应 deadline。
- 首次到期进入一次有界确认窗口；不能用“超时了多少毫秒”排除临界时刻恢复。
  第二次到期无条件 fail closed，总等待最多两个超时窗口（不含宿主挂起时间）。
- SharedArrayBuffer 只报告执行／投递进度，不作为持久化 ACK；仍必须收到真实结果
  才发布新记忆。没有第二次提交、自动重放或不断续期。
- 真正超时、线程异常、意外退出继续 fail closed，并提供操作类型、耗时、阶段、
  退出码等脱敏诊断；不返回文件内容、消息或路径。
- `/health.ok` 同时要求记忆可写，不能因两个 QQ 都在线而掩盖持久化故障。

验证：`npm run test:memory`、`npm run test:memory-watchdog`。
隔离的真实数据副本约 33 MB，单次 open 约 2.1 秒、commit 约 5 秒；
该测量不是 P95 指标，也不证明所有历史超时的原因。

## 真实记忆的起点与不可突破的边界

本轮只读核对旧状态：18,651 个扫描项、18,555 个候选、43 人，已发布 0 项；
15,833 项可见候选尚未完成语义整理，3 个未知批次共 96 项不得重放。
其中大量条目缺原始来源或逻辑 Bot 归属，不能把模型整理文本提升为事实。

语义阶段应分别报告：处理／提案／去重／冲突／未知／仍未处理／实际发布。
扫描完成不是整理完成；语义分类完成也不是所有历史人物事实都已核实。
同 QQ、原会话、逻辑 Bot 和来源绑定的边界始终有效，纠正及删除记录不能复活。

扫描结束后新增独立的有界语义游标，默认一次调用、显式单轮最多 100 次，
仍受原重建总预算和账号自主调用预算约束。每次最多 16 个同 QQ、同会话、
同历史逻辑身份的代表项；采用短别名、实际网关 usage、保守输入与输出额度。
模型只提出分类、重复、矛盾及时间变化提案，不授予来源或身份。
精确同范围、同值、同类型的候选可复用提案，不复用证据或提高等级。

原未知回执没有起始游标。源 worker 只在原固定快照中有界查找，必须同时匹配
原批次行 SHA-256、行数、扫描量及结束游标，才记录精确排除项。生产的三个
旧批次均已匹配，96 项继续隔离；没有重放旧请求，也没有用 offset 减行数
猜测。无法证明的批次保留保守前缀隔离，恢复证明本身不启动模型工作。
新的语义未知批次隔离实际暴露的 ID，继续时重新检查本页尚未暴露的其他项，
不能因为同页一个人的请求失败就把其他人的候选一起吞掉。

## 通用主人语义入口

- 验证真实主人私聊 Carrier 后，复用现有分类器区分查询、一次性命令、指导、
  委托、修正及普通聊天，不再要求固定中文命令前缀。
- 分类得到的 native command/query 交回原 Owner Router：同一份已验证候选、
  同一 claim、当前权限、修订和最终发送闸门，不进行第二次语义解析。
- `/bot`、`/owner` 保持原确定性路由。自然普通聊天可能使用一次分类后回正常
  聊天；这不是零成本，也不把普通聊天当已执行命令。
- 返回真实宿主查询数据或 confirmed/accepted/failed/uncertain/blocked 状态；
  模型自述不能成为回执，不确定操作不自动重试。

## 委托重启、暂停与重新授权

- 重启恢复只读；普通“继续”不解锁旧写入。暂停、撤销、取消、重启和重新授权
  均撤销旧 pending/claimed 唤醒及工具授权，保留审计历史。
- 重新授权必须来自新鲜、真实的主人事件并带完整新目标。宿主直接核验明确
  确认，不由模型自行挑选 evidence 获得授权。例如：
  `我确认重新授权 task_实际编号：本次完整新目标。`
  否定、假设、引用、疑问及普通恢复均不解除只读。
- 新 executionGeneration 清空旧观察、摘要、补充和准备缓存。旧私有材料保留
  审计，不进入新计划或群结果；工具及缓存同时校验 generation。
- 旧回执、累计预算不重置。未解决的 broker 副作用阻止重新授权；旧不确定／
  受理／成功写入按规范化参数摘要阻止重放；摘要缺失或损坏时保守阻止该能力。
- 新一代仍需当前身份、quiet、范围和配置修订有效，由新实际回执确认结果。

## 回滚

本机状态目录 `backups/p0-beta36-*`／`p0-beta37-*` 保存旧 App、配置、完整 data
及 manifest；不属于 Git 或公开 App。协议容器、登录卷和 Keychain 未改动。
先停止 App/桥接再恢复旧 App，不覆盖后续用户配置或新记忆。需要回滚语义状态时
先保存当前版本，再比较恢复；不能让两个 writer 同时打开仓库。回滚不重放旧未知
发送，也不能把旧版暂时恢复可写称为 watchdog 根因修复。

## 验收分层

1. 合成测试与假 OneBot：验证契约、失败与撤销，不能当作真实效果分数。
2. 真实模型与隔离数据：记录结构化输出通过率、可信 usage 与缺失值。
3. 生产记忆发布：须备份、单 writer、版本检查，列明实际发布及保留的未核实项。
4. App 部署：另行授权，保留旧版本与恢复路径，不覆盖北邮及 MiMo 的当前绑定。
5. QQ 写入：本轮默认不发实测消息；不能将假协议或模型候选称为实际发送回执。
