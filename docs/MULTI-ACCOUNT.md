# 多账号管理

账号是独立的 QQ 登录连接，不再按列表位置自动赋予主号或备用号身份。
管理页侧边导航不变：「账号状态」负责连接、登录和启停协议端；「账号功能」负责机器人身份、功能、发送内容、参与范围和模型。

## 添加与启用

1. 在「账号状态」选择「添加账号」。可新建由应用管理的 SnowLuma 容器，或连接已有 OneBot WebSocket 服务。
2. 填写 QQ 和机器人名称；受管容器分配互不冲突的端口。新账号默认不参与机器人工作，仅允许文本发送。
3. 启动协议端，打开 WebUI/noVNC 完成人工登录，再检测 QQ 身份。
4. 在「账号功能」完成权限设置后启用。新增账号数量不受旧的备用账号数组上限限制；实际并发受本机和模型服务能力约束。

三个操作不同：

| 操作 | 机器人消息处理 | QQ/OneBot 连接 | 历史数据 |
| --- | --- | --- | --- |
| 暂停机器人 | 停止回复和新任务；继续收集上下文 | 保留 | 保留 |
| 停止协议端 | 停止收发连接 | 受管容器停止；外部连接断开，不停止外部服务 | 保留 |
| 移除账号 | 从工作列表归档 | 停止该账号桥接 | 保留记忆、存档、任务与协议数据，不删除卷 |

有活动任务、接管组或自动化引用时，需要先处理这些依赖，才能移除账号。

## 逐账号设置

- 身份：账号名称与机器人自称分别保存。账号名称用于管理列表和身份识别；自称用于对话，可以是“我”或其他称呼，不要求与名称相同，也不修改 QQ 昵称。旧配置保留原有称呼；自称留空时使用本账号名称。提示词、风格和记忆不会因修改自称而被重写。
- 保存状态与账号选择分开：账号卡片始终使用“编辑账号”入口；编辑区显示保存中、已保存、未保存修改、失败或版本冲突。每次只保存当前标签，其他标签的草稿继续保留。
- 功能：聊天、任务、主动参与、自动化、联网搜索、识图、语音识别和学习模式。聊天/任务/全能只是快捷选择，不替代细项开关。
- 发送内容：文本、图片、语音、视频、文件分别允许。允许某种类型不代表协议端一定支持；发送仍需真实回执。禁用语音时不能改为音频附件绕过权限。
- 范围：群聊、私聊及账号级群白名单，与全局会话限制共同生效。
- 模型：从 API 管理中已有的方案选择；留空继承全局。任务的「继承本账号问答」不会误用另一个账号的问答模型。

旧版群聊 quiet 设置继续作为默认值；指定机器人的 `/bot a quiet` 仅停止该机器人在本群的聊天、任务进度和自动化发送，不影响其他机器人。quiet 期间继续收集消息，只有管理员的恢复指令可以解除对应机器人的 quiet。

账号活跃度是默认值，本群针对该机器人的设置优先于账号默认。单机器人群使用不带编号的控制指令时，也只修改该机器人的本群设置；之后加入的其他机器人不会继承这次修改。历史共享设置仍作为兼容默认读取，不会批量清理旧记忆。

## 群聊控制指令

- 群内只有一个本项目机器人时，继续使用 `/bot status`、`/bot voice mixed` 等旧指令。
- 群内有多个时，不带编号的 `/bot` 或 `/bot quiet` 不执行控制操作，由列表中第一个在线机器人提示编号与名称、QQ 对应关系。
- 使用 `/bot a status`、`/bot b mode restrained`、`/bot b voice mixed`、`/bot a quiet 10m`、`/bot a resume` 分别控制。`/bot a` 显示该机器人的帮助；帮助中的示例自动带编号。
- 编号按当前群实际成员名单和管理页账号顺序生成，主备接管组算一个机器人。断线不会让后续机器人临时改号；成员增减或管理列表调整后，应重新发送 `/bot` 核对编号。
- 目标离线或编号不存在时，仅提示、不转交其他机器人执行。群成员名单暂不可读时，不猜测编号，也不执行修改。
- quiet、活跃度、语音模式/音色和学习开关按机器人隔离；群友资料、群记忆和聊天存档仍共享，修改或清理存档会影响本群共同存档。
- 私聊不使用群内编号，沿用原有私聊指令和授权规则；机器人在管理页被暂停时不能借群指令绕过暂停。

## 独立账号与接管组

默认各账号平级，独立使用人格与自我记忆；群内事实和成员资料可以共享。明确 @ 谁就由谁处理；普通群消息由每个符合条件的账号自行判断，不设置“最多两个账号回复”的硬上限。所有账号共用群发送节流，避免同时刷屏。机器人之间的消息默认不触发新的自动回复循环。

“独立判断”不代表每条消息都让所有账号回复：各账号使用自己的本群档位、冷却和能力开关，未命中回复条件则旁听。明确提问和接话信号与主动参与分别判断；关闭主动参与不能阻断正常的定向问答。

需要多个 QQ 登录代表同一个机器人时，创建「接管组」：

- 每个账号最多属于一个接管组，组内至少两个账号。
- 成员顺序表示优先顺序；选定一个成员作为共享机器人设置的来源。
- 组内使用同一份名称、风格、功能、内容权限、范围和模型策略；QQ、容器、端口与连接仍分别保存。
- 只有组内当前验证可用的成员发言；接管依赖强异常与替代账号的收发证据，并受冷却保护。
- 可以同时存在多个接管组和组外独立账号，不能把某一组的故障当成所有账号的故障。

自动化规则只绑定一个账号或一个接管组。接管组规则由当前成员发送，单次计划不会让所有成员各发一遍。未明确绑定的旧规则保留单发送者兼容行为。

## 配置、迁移与数据保护

### 每个账号有自己的风格

账号的 `style.systemPrompt` 是独立保存的完整提示词，留空表示尚未配置，不会回退到另一个账号。旧版本生效的提示词在首次读取时原样转换为账号快照；原小跟班文字、旧模板和自我记忆都保留。首次写入前备份配置与记忆。

新建账号可「从零开始」或「复制已有账号风格」。复制只是当时文字的一份副本，之后互不影响；不会复制 QQ 身份、权限、启用状态、记忆或已启用自动化。模板也是复制来源，不再是实时继承关系。明确创建的接管组仍代表同一个机器人，使用一份共享策略。

### 规则放在哪里

| 规则类型 | 管理位置 | 执行依据 |
| --- | --- | --- |
| 早问好、晚问候、每日总结、定时主人私聊 | 自动化 → 原有例行规则 | 时间、原群范围和发送者策略；保留旧去重记录 |
| 新增定时或指令触发动作 | 自动化 → 自定义规则 | 显式会话和账号 / 接管组绑定 |
| 接梗、称呼、语气、人格偏好 | 问答 → 该账号风格 | 独立提示词，不是调度器 |
| 主动发言、quiet、语音收发、可发送内容 | 账号功能 / 本群控制指令 | 结构化开关与权限，优先于提示词 |
| 本地文件、浏览器、任务权限 | 任务与 Agent | 逐任务授权，不能用口头承诺代替 |

自动化页先选账号。独立账号的规则保存在 `automation.accounts[accountId]`；明确的主备接管组共用 `automation.groups[groupId]` 一份规则，由当前成员执行。新账号的目录为空，不自动复制其他账号的问候、总结或定期私聊。账号的自动化功能开关是唯一启停来源。

原 `dailyMessages` / `hourlyChat` 以及未绑定账号的旧规则，只迁移到原始账号（或其明确接管组），不按当前在线/默认账号推断。无法确定归属的规则进入 `automation.unassigned`，不执行。原始规则字段和执行记录保留；新占用键加入账号/组身份，只有原归属目录兼容旧占用记录。口头承诺不自动启用，风格与记忆不删除。

本机管理接口为 `GET/PATCH /api/automation/accounts/:accountId`，返回此账号的规则、例行规则、归属与修订。保存携带 `expectedRevision`，冲突时保留草稿，不自动重试。旧例行接口须显式提供 `account_id`。界面切换账号保留各自草稿；测试、配置保存不会发送 QQ 消息。有规则的账号修改接管组关系会明确拒绝，避免隐藏或擅自迁移规则，须先显式处理规则归属。

新结构为 `accounts.version = 2`、`accounts.items` 和 `accounts.failoverGroups`。稳定账号 ID 是配置、任务和自我记忆的关联键；修改名称或列表位置不会改身份。

旧 `accounts.primary`、`accounts.standbys`、`accounts.topology` 继续作为兼容视图可读。旧主备配置迁移为一个接管组；旧分工配置迁移为独立账号。迁移不自动切换模型、密钥、账号连接或原有风格；首次写入升级结构前保留回滚快照。旧客户端按账号 ID 更新，不能用短数组覆盖新添加的账号。

导入备份采用现有整体替换及回滚流程，不自动合并记忆。普通备份不包含密钥和 QQ 登录态，完整迁移包仍要求密码加密。

## 开发验证

```sh
npm run test:accounts
npm run test:account-isolation
npm run test:bot-commands
npm run test:features
npm run test:api-center
npm run test:backup
npm run test:config-revision
```

账号集成测试使用临时目录、模拟协议端和模型回执，不向真实 QQ 发送测试消息，不操作真实 Docker。

回复从入站开始绑定账号和连接会话；生成、语音合成及排队期间连接换绑后，旧内容不会借用新身份发送。发送前再次检查账号权限、quiet、配置版本和会话。即使同一连接发生 A → B → A，旧任务及探测回执仍会失效。

账号隔离回归覆盖独立回复判断、命令/档位/语音设置、健康证据、真实发送队列以及换绑竞态。共享群记忆与群级发送间隔是有意保留的；独立判断不等于每条消息必须由所有账号回复，也不代表所有模型调用并行。
