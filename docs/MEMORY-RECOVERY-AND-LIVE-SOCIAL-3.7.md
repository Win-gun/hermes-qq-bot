# Hermes 3.7：人物记忆恢复与真实社交验收

## 起点

2026-11-05（北京时间）核对 GitHub `main` 基线 `0a633bb`。生产 beta.39 的两个 OneBot 均在线，记忆仓库可写。历史任务仍暂停：扫描 18,651 项，留下 18,555 个候选，涉及 43 人；18,547 个候选没有历史 Bot 归属。7 条模型提案未升级为正式事实。任务的旧发布游标已结束，0 条历史人物记忆获发布；最后一条已截断的语义请求仍有持久隔离记录。保留原用量账本（20,077 个已知 Token，4 次用量未知），不重放未知请求。

4,926 条未命中归档的候选中，25 条能关联旧提取队列的会话、发送者、消息 ID 与事件时间，3 条还可确定性绑定内容；25 条均缺历史 Bot 归属证据。另有 1,098 条仅命中会话／消息 ID 的 ACK，不含足以补齐归属的记录。本轮 12 次生产只读人物检索正常返回，实际可检索 0 人。既有 13 条模型处理及 7 条提案仍保留；本轮未为这批材料调用模型，实际恢复和发布均为 0。

新版将旧摘要与已验证原文分开：旧摘要不能用同文匹配补造消息 ID；只把已核验、尚需分析的候选纳入付费语义工作，模型输出仍是提案。新口语识别保留「最近」「目前」和比较限定；转发、引文、反讽、假设、提问和身份不清不按事实发布。固定快照的第二版发布游标可独立续扫，不改旧游标、预算或隔离回执。遇到仍被隔离的未知写入不跳过原安全闸门。没有合格的历史事实，不为跑进度而恢复付费扫描。

## 新消息：从真实入口到人物索引

以前即使已有原始来源回执，普通自述也要等后台模型输出和提取校验才能投影进人物索引。3.7 让纯文本、非引用且可核实的群内本人自述随原有 `MemoryIntake` 一起提交。它使用实际发送人、消息 ID、会话、Carrier 和原始发送时间；在提交时重查当前身份和配置。既有后台提取继续处理更复杂的内容，不是这条路径的前提。不增加模型调用、持久化提交、发送或执行器。

公开自述首先是该人在该时间的说法，不是永久事实。单条自述只供获准的群聊内部理解；原群撤销或当前群不再允许时，不跨群投影。不同逻辑 Bot 隔离，私聊和引用不进入这条路径。既有更正、删除和撤销控制仍优先；普通口语中的含糊改变不会由系统自行裁定或删除旧事实。

隔离 bridge 通过假 OneBot 收到普通自述，实际写入 MemoryRuntime，重启后通过人物 API 读回。跨群 API 的对外查询保持拒绝，真实回复组装器在另一获准群得到内部理解；没有接收原消息的 Bot 查不到。私聊来源不混入群提示词，删除后同一事实的新输入也不能复活原记录。此项是隔离闭环，不是生产 QQ 验收。

## 真实社交验收口径

- 主人连续委托：必须是主人本人从 QQ 发出新的目标、补充和修正；须分别核对持久指导、任务 ID、工具实际结果及回执。假 OneBot、旧指令历史和模型自述都不能代替。
- 自主表情：模型应有选择文字、表情、两者或沉默的余地。明确指令发图不算自主选择；搜索命中、图片准备和协议确认分别记账。
- 已授权的 QQ 测试群当前允许两账号的常规回复，但不在两者已保存的 Social Agent 或表情表达范围内。直接 `@` 可走常规 ReplyPlan；它没有临时 Memecub 搜索回调，不能作为自主搜索替代测试。未扩大范围；真实自主表情仍未验收。
- 同一组合提示的合成对照：`direct` 2,377 → 1,800 字符，`social` 2,737 → 2,160，任务模式字节不变。反思轮只展示可用的只读工具，耗尽工具预算后不展示工具；实际动作仍由原闸门校验。不是实际 Token 节省或真人自然度评分。
- 参考 [qq-bridge](https://github.com/Derpyu520/qq-bridge) 的行为设计；不移植受其 [许可证](https://github.com/Derpyu520/qq-bridge/blob/main/LICENSE) 约束的代码、人格或原文。
