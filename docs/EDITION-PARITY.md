# WebUI 与 macOS App 功能一致性

两种入口运行同一份 `src/bridge.js`、`src/backup-service.js` 和 `public/admin.html`。区别是宿主能力的呈现方式，不是机器人行为或数据格式的分叉。

| 能力 | 浏览器 WebUI | macOS App |
| --- | --- | --- |
| QQ/OneBot、模型、搜索、识图、记忆、任务、存档 | 同一桥接服务 | 同一桥接服务 |
| 默认数据目录 | `~/Library/Application Support/Hermes QQ Bot/` | 同左 |
| 启动、停止、重启、登录启动 | 本机宿主 API / LaunchAgent | 管理页及菜单栏；附着 Web 宿主时调用宿主 API |
| 普通与完整备份、进度、取消、恢复 | 管理页上传/下载 | 同一管理页，加原生文件选择 |
| 旧项目迁移 | 输入本机项目绝对路径，显式执行 | 原生目录选择；附着 Web 宿主时走同一迁移 API |
| Finder 定位、菜单栏 | 浏览器无此原生能力，使用下载或本机文件管理器 | 原生能力 |

WebUI 启动：安装 Node.js 22.12–25、Docker Desktop 和 Hermes CLI 后，在解包目录执行 `npm ci --omit=dev`、`npm run web:start`，访问 `http://127.0.0.1:6200/admin`。`scripts/start-web.command` 会先检查本机依赖。首次启动从安全模板创建配置，不自动导入旧数据。正式接管前，在“备份与迁移”中显式检查并迁移旧项目，或导入备份。

两种入口不能同时各自启动一个桥接。App 检测同一状态目录的 Web 宿主后会附着；不同状态目录、被占用端口或旧版独立桥接应先停止并处理，不可绕过检测强行并行运行。迁移会停机并核验账户和模型；迁移前另行保留包含 Docker 登录卷的完整备份。QQ 仍可能因新设备策略要求重新扫码。

发布前至少使用隔离状态目录逐一测试：首次启动、桥接启停、账号状态、模型设置、普通/完整备份、进度与取消、恢复、旧项目迁移失败回滚，以及 App 附着 Web 宿主后没有重复桥接。不要用真实 QQ 发送测试消息。当前清单是验收标准，不表示这些场景都已经完成实机验证。
